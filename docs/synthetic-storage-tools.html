Synthetic Healthcare database tools

The Synthetic database tools tab composes shared Framework inspection and recovery tools. It is a local fictional-data exercise. It has no clinical authorization, real patient access control or care approval function.

  1. Open the Healthcare native application and select Synthetic database tools. The tab appears when the linked Framework provides both database maintenance and saved receipt inspection.
  2. Confirm that you selected a fictional exercise database you may inspect and copy. This acknowledgement enables local actions; it is not a login, permission grant or automatic check of database contents.
  3. In the maintenance panel, select the existing database and choose Check database. Read any diagnostic result. A completed SQLite check is not validation of healthcare information.
  4. Choose a new destination and select Create backup or Recover to new database. Both retain the source and refuse to overwrite an existing destination. A copy includes every table in the database, not only synthetic profiles.
  5. In the receipt panel, choose the original import destination database and enter the receipt ID used when importing a profile. View receipt checks the receipt itself. Verify imported history also verifies the original imported revisions. Neither proves who authored them.

The application keeps the window open while an accepted operation is pending and selects this tab to show the work. The worker uses the paths captured at admission. Changing visible inputs or unchecking the acknowledgement does not undo an already accepted copy. Recovery does not switch the profile or review-note editor to the new database; select and inspect that store separately.

If an action is denied, check the fictional-data acknowledgement and the selected absolute paths. If a destination already exists, choose a different filename. If SQLite is busy, finish the other transaction and try again. Failed copies may leave a newly created partial file for inspection; existing files are retained.
