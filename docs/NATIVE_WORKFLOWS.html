Umicom Healthcare user guide: synthetic access and local records

Use invented practice records in this application. The access workflow is a simulation for learning and development. It does not provide clinical treatment, prescriptions, patient authentication or a connection to a care provider.

Complete a synthetic access exercise

  1. Open the access workspace and expand its action sections.
  2. Choose Register patient to register the synthetic participant.
  3. Choose Create request, then Full offer.
  4. Choose Accept offer, then Simulate funding.
  5. Choose Reserve for 5 minutes, then Record collection.
  6. Inspect the details. The completed exercise should show Collected: 1.

These actions operate on the local simulation state. They do not collect a real payment or establish a clinical permission. Perform the steps in order because later actions depend on the earlier state.

Move between tools

Use the workspace tabs to move between access, review records and any optional profile or storage tools included in your build. Return to the access tab and check that its result is unchanged. Tabs are views of their own Framework services; a note saved in a record store is not automatically part of the access simulation.

Work with a local record

  1. Open the record editor. Choose a database location you can access before trying to find or save records.
  2. Create or open a practice record and read its current revision. A revision identifies a saved version.
  3. Make the intended changes and save through the editor. Read any conflict message before retrying; another writer may have changed the saved revision.
  4. If you use draft recovery, inspect the recovered content before accepting it.
  5. Save or deliberately discard changes before closing the workspace.

With no database selected, storage actions remain unavailable. A disabled button should not create or read a database through a synthetic activation.

Close and reopen

  1. Finish or cancel any active storage operation.
  2. Use the normal close control. If a draft or an operation prevents closure, follow the selected tool’s save, discard or cancellation controls.
  3. Close again after resolving that state. The application must not silently lose a draft.
  4. Reopen the chosen store to confirm saved content. Do not expect the in-memory access exercise to survive an application restart.

Controls and limits

AreaWhat to check
Synthetic access actionsEach accepted action updates the displayed state; an invalid sequence leaves it unchanged.
Record editorStorage requires an explicit location; saves and recovery report their outcome.
Profile importReview the proposed data before applying it. Opening an import view is not an import.
Window closePending work is handled before the window closes; a clean workspace can close.

See synthetic storage tools for the optional inspection, recovery and transfer workflows. If a tool is absent, check the build configuration rather than assuming its page exists.
